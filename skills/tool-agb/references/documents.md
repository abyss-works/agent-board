# 기록 문서 등록

기록 문서(결정, 사고, 보고, 구현 기록, 조사 자료)를 agb에 올리거나, 올린 문서의 상태와 관계를 고칠 때 이 문서를 따른다. agb가 받는 문서의 형식과 메타데이터는 agb가 정한다. 올리는 쪽의 폴더 이름이나 문서 규칙은 agb가 알지 못하므로, 맞지 않는 문서는 올리는 쪽이 이 문서대로 맞춘다.

- 서버의 기록 문서는 원문을 고치거나 지울 수 없다. 같은 이름에 다른 원문을 올리면 거절한다. 덮어쓰려 하지 않는다.
- 올린 뒤에는 아카이브 표시와 관계만 고친다(8절).
- 프로젝트 키(`<KEY>`)는 저장소의 `.agb.json`에 있는 `project`다. `.agb.json`이 없는 저장소는 문서를 자동으로 올리지 않는다. 수동으로 올릴 때는 `-p <KEY>`를 준다.

## 1. 받는 문서

- 마크다운(`.md`), UTF-8, 256KB 이하인 파일만 받는다.
- 서식(`_`로 시작하거나 `.example.md`로 끝나는 파일)은 받지 않는다.
- 로그, 코드, 데이터 파일은 올리지 않는다.
- 문서는 두 가지다.

| 구분 | 언제 쓰나 | 이름 | 검증 |
|---|---|---|---|
| 일반 문서 | 새로 쓰는 기록 | `yyyy-mm-dd-HHMM-<종류>-<slug>.md`. `slug`는 영문 소문자, 숫자, 하이픈 | 엄격 |
| 가져온 문서(`imported`) | 위 형식을 따르지 않는 기존 문서를 옮겨 올릴 때 | 저장소에서 본 상대 경로(`notes/design.md`) | 느슨 |

- 종류는 `decision`, `incident`, `report`, `implementation`이다. `other`는 가져온 문서에만 쓴다.
- 새로 쓰는 기록은 일반 문서로 쓴다. 가져온 문서는 이름 형식이나 프런트매터가 맞지 않아 일반 문서가 될 수 없는 문서에만 쓴다.

## 2. 메타데이터

필드마다 인자, 원문 프런트매터, 대체값 순으로 정한다. 인자가 있으면 프런트매터를 대신한다.

| 필드 | CLI 인자 | 프런트매터 키 | 대체값 |
|---|---|---|---|
| `kind` | `--kind <종류>` | `kind` | 일반 문서는 이름의 종류. 가져온 문서는 `other` |
| `date` | `--date <yyyy-mm-dd[ HH:MM]>` | `date` | 일반 문서는 이름의 날짜와 시각. 가져온 문서는 이름 앞의 날짜, 없으면 비움 |
| `title` | `--title <제목>` | `title` | 일반 문서는 없음(필수). 가져온 문서는 첫 `# ` 제목줄, 없으면 비움 |
| `tags` | `--tag <태그>`(반복) | `tags` (`[a, b]` 목록) | 빈 목록 |
| `supersedes` | `--supersedes <문서 이름>`(반복) | `supersedes` | 빈 목록 |
| `related` | `--related <문서 이름>`(반복) | `related` | 빈 목록 |
| `issues` | `--issue <이슈 키>`(반복) | `issue`, `issues` | 빈 목록 |
| `archived` | `--archived` | 읽지 않는다 | `false` |
| `imported` | `--imported` | 읽지 않는다 | `false` |
| `path` | `--path <상대 경로>` | 읽지 않는다 | 올리는 파일의 저장소 기준 상대 경로 |

- 인자로 준 목록은 프런트매터의 같은 목록을 통째로 대신한다. 합치지 않는다.
- 프런트매터에서 읽는 키는 `kind`, `date`, `title`, `tags`, `supersedes`, `related`, `issue`, `issues`뿐이다. 값은 한 줄이다.
- `archived`는 프런트매터에 적어도 읽지 않는다. 아카이브로 올리려면 `--archived`를 주거나 `.agb.json`의 규칙에 적는다.
- 본문에 적은 이슈 키는 관계로 읽지 않는다. 이슈와 잇으려면 `--issue`나 `issue:` 프런트매터를 쓴다.
- 일반 문서는 `title`이 필수다. 프런트매터에 없으면 `--title`로 준다.
- 자리표시자(`<...>`)가 남은 값은 거절한다. 서식에서 만든 파일은 모두 채운다.

## 3. 상태

문서의 상태는 저장하지 않고 서버가 계산한다. 우선순위는 아카이브, 대체됨, 유효 순이다.

| 상태 | 뜻 | 조건 |
|---|---|---|
| 유효(`current`) | 지금 판단의 근거 | 아래 둘에 해당하지 않음 |
| 대체됨(`superseded`) | 다른 문서가 전체 대체한 문서 | 다른 문서의 `supersedes`가 이 문서를 가리킴 |
| 아카이브(`archived`) | 판단 근거가 아닌 배경과 조사 자료 | 올릴 때나 올린 뒤에 `archived`로 표시함 |

- 조회 명령은 기본으로 유효한 문서만 찾는다. 대체됨과 아카이브는 `--state`로 넓힌다(`superseded`, `archived`, `all`).
- 이전 결정을 뒤집는 새 기록을 올릴 때는 새 기록의 `supersedes`에 이전 기록의 이름을 적는다. 이전 기록의 파일은 고치지 않는다.
- 결정 기록의 `status`(채택, 기각, 보류)는 문서 상태와 별개다.

## 4. 참조 표기

- 문서 참조는 같은 프로젝트에 올라간 문서의 이름이다. 일반 문서는 파일명(`2026-10-20-1544-decision-x.md`), 가져온 문서는 경로(`notes/design.md`)다. 글자가 같아야 풀린다.
- 이슈 참조는 이슈 키(`AGB-12`)다. 다른 프로젝트의 이슈도 된다.
- 한 값에는 이름 하나만 쓴다. 설명 문장을 붙이지 않는다.

```yaml
supersedes: 2026-10-18-0900-decision-queue-draft.md
related: [2026-10-17-1000-report-queue-survey.md, 2026-10-19-1100-incident-queue-lock.md]
issue: AGB-21
```

- 전체 대체만 `supersedes`에 쓴다. 한 문서를 통째로 대신하는 경우다.
- 일부만 대체하거나 보완하거나 참고하면 `related`에 쓴다. 문장이 섞인 `supersedes`는 거절한다(`not_a_name`).
- 이슈의 참조 `doc:<문서 이름>`과 `issue:<이슈 키>`도 같은 이름과 키를 쓴다. 대상이 없으면 거절하므로 문서를 먼저 올리고 참조를 건다.
- 서로 참조하는 문서는 대상을 먼저 올린다. 이름순으로 올리면(시각이 이름 앞에 있다) 이전 기록이 먼저 올라간다.

## 5. 오류와 대처

종료 코드가 1이면 stderr를 읽는다. 대처할 수 없는 거절은 파일명과 사유를 최종 보고에 쓴다.

| 응답 | `reason` | 뜻 | 대처 |
|---|---|---|---|
| 409 | `immutable` | 서버에 같은 이름의 다른 원문이 있다 | 원문을 고쳐서 다시 올리지 않는다. 뜻을 바꾼 기록이면 새 기록을 쓰고 `supersedes`로 잇는다. |
| 409 | `metadata_differs` | 원문은 같은데 메타데이터가 서버의 값과 다르다 | `details`에 다른 필드가 나온다. 아카이브와 관계는 8절 명령으로 고친다. 나머지 필드(`kind`, `date`, `title`, `tags`, `imported`, `path`)는 고치지 않는다. 서버의 값을 그대로 둔다. |
| 409 | `cycle` | `supersedes`가 순환한다 | 대체 방향을 확인한다. 새 기록이 이전 기록을 대체한다. |
| 422 | `unresolved` | `supersedes`, `related`, `issue`가 가리키는 대상이 서버에 없다 | 대상 문서를 먼저 올리거나, 이슈 키를 확인한다. 가져온 문서(`--imported`)는 이 오류 대신 경고(`warnings`)로 등록되고, 대상이 나중에 올라오면 풀린다. |
| 422 | `not_a_name` | `supersedes`나 `related`의 값이 이름이 아니다 | 이름만 쓴다. 부분 대체는 `related`로 옮긴다. |
| 422 | `self_reference` | 자기 자신을 가리킨다 | 값을 지운다. |
| 422 | (필드별) | 이름 형식, 종류, 제목, 자리표시자, 크기 위반 | `details`의 필드를 고친다. 이름 형식이 맞지 않는 기존 문서는 7절로 올린다. |
| 400 | | `location` 같은 없어진 매개변수 | `--state`(상태), `--imported`(가져온 문서)로 바꾼다. |
| 409 | `project_not_active` | 프로젝트가 활성이 아니다 | 프로젝트 상태를 확인한다. |

## 6. 저장소 설정 `.agb.json`

저장소 최상위에 둔다. 이 파일이 있는 저장소가 agb를 지식 저장소로 쓴다. 파일이 없으면 CLI는 문서를 자동으로 올리지 않는다. CLI가 읽고 서버는 알지 못한다.

| 키 | 뜻 |
|---|---|
| `project` | agb 프로젝트 키. 필수 |
| `auto_sync` | `true`이면 `agb agenda` 같은 명령이 커밋한 문서 중 서버에 없는 것을 올린다 |
| `documents` | 올릴 파일의 규칙 목록. 위에서부터 처음 맞는 규칙을 쓴다. 어느 규칙에도 맞지 않는 파일은 올리지 않는다 |
| `new` | `agb doc new`가 쓰는 서식과 채울 값 |
| `follow_up_headings` | 후속 항목을 알리는 절 제목 목록 |

`documents`의 규칙 키는 다음과 같다.

| 키 | 뜻 |
|---|---|
| `glob` | 저장소 기준 경로 패턴. `*`는 한 조각 안의 글자, `?`는 글자 하나, `**`는 0개 이상의 폴더 |
| `name` | 서버에 올릴 이름. `base`는 파일명, `path`는 저장소 기준 경로 |
| `kind` | 기본 종류(선택) |
| `archived` | 아카이브로 올림(선택, 기본 `false`) |
| `imported` | 가져온 문서로 올림(선택, 기본 `false`) |

- 규칙의 값은 인자와 같다. 파일 하나를 올릴 때 CLI는 규칙의 값을 기본으로 쓰고, 명령줄 인자가 있으면 인자가 이긴다.
- CLI는 서버가 받지 않는 파일(서식, `.md`가 아닌 파일, 256KB 초과)을 규칙과 상관없이 올리지 않는다.
- 커밋하지 않았거나 커밋 뒤 바뀐 파일은 올리지 않는다.
- 서버에 없는 파일만 올린다. 이미 있는 파일의 메타데이터 차이는 고치지 않는다.

예시: `history/`에 일반 문서를, `archive/` 바로 아래에 아카이브를, 이전 체계 폴더에 가져온 문서를 둔 관리 저장소다.

```json
{
  "project": "AGB",
  "auto_sync": true,
  "documents": [
    {"glob": "history/*.md", "name": "base"},
    {"glob": "archive/*.md", "name": "base", "archived": true},
    {"glob": "archive/*/**/*.md", "name": "path", "imported": true, "archived": true},
    {"glob": "decisions/*.md", "name": "path", "imported": true, "kind": "decision"},
    {"glob": "reports/*.md", "name": "path", "imported": true, "kind": "report"},
    {"glob": "incidents/*.md", "name": "path", "imported": true, "kind": "incident"}
  ],
  "new": {
    "template": "history/_{kind}.md",
    "output": "history",
    "values": {"project": "agent-board", "author": "claude"}
  },
  "follow_up_headings": ["남은 것", "미확인", "후속"]
}
```

- 저장소가 쓰는 폴더 이름은 저장소의 `.agb.json`에만 있다. agb는 이 예시의 폴더 이름을 알지 못한다.
- `agb init -p <KEY>`는 `documents`가 빈 파일을 만든다. 규칙을 채우기 전에는 아무것도 올라가지 않는다.
- `.agb.json`을 새로 쓰거나 고쳤으면 `agb doc sync -p <KEY>`로 서버에 없는 문서가 무엇인지 보고 올린다.

## 7. 맞지 않는 문서를 올리기

문서 형식이 agb의 형식과 달라도 원문은 고치지 않는다. 원문은 그대로 두고 메타데이터를 인자로 넘겨 맞춘다. 파일과 서버의 사본이 같으므로 다시 올려도 충돌하지 않는다.

1. 일반 문서가 될 수 있는지 본다. 파일명이 `yyyy-mm-dd-HHMM-<종류>-<slug>.md` 형식이면 된다. 프런트매터가 없거나 `title`이 없으면 인자로 준다.
   ```
   agb doc put <파일> -p <KEY> --title "<제목>" --tag <태그> --issue <이슈 키>
   ```
2. 파일명이 형식이 아니면 가져온 문서로 올린다.
   ```
   agb doc put <파일> -p <KEY> --imported --kind decision --date 2026-10-17 --title "<제목>"
   ```
   - 이름은 저장소 기준 상대 경로다.
   - 날짜는 이름의 날짜, 제목은 첫 `# ` 제목줄로 채워진다. 맞지 않으면 인자로 준다.
3. 이전 문서가 더는 판단 근거가 아니면 아카이브로 올린다.
   ```
   agb doc put <파일> -p <KEY> --imported --archived
   ```
4. 이전 문서를 새 기록이 대체했으면 새 기록에 `--supersedes <이전 문서 이름>`을 준다. 이전 문서가 서버에 없으면 먼저 올린다.
5. 같은 설정을 여러 문서에 반복해야 하면 인자 대신 `.agb.json`의 규칙으로 쓴다(6절).

## 8. 올린 뒤 고치기

고칠 수 있는 것은 아카이브 표시와 관계(`supersedes`, `related`, 이슈)뿐이다. 변경마다 활동 기록이 남는다. 원문, 종류, 날짜, 제목, 태그는 고치지 않는다.

| 하려는 일 | 명령 |
|---|---|
| 아카이브로 표시 | `agb doc archive <PROJECT> <이름>` |
| 아카이브 해제 | `agb doc unarchive <PROJECT> <이름>` |
| 관계 더하기 | `agb doc link <PROJECT> <이름> --supersedes <대상>` / `--related <대상>` / `--issue <이슈 키>` |
| 관계 빼기 | `agb doc unlink <PROJECT> <이름> --supersedes <대상>` / `--related <대상>` / `--issue <이슈 키>` |

- `link`의 대상은 4절의 이름과 키다. 일반 문서에서 풀리지 않는 대상은 거절한다(`unresolved`).
- 지금 상태와 관계는 `agb doc get <PROJECT> <이름>`으로 본다. 변경 이력은 문서의 활동 기록에 있다.
- 이미 그 상태이면 아무것도 바뀌지 않고 성공한다.
