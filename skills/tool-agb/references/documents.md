# 기록 문서 등록

기록 문서(결정, 사고, 보고, 구현 기록, 조사 자료)를 agb에 올릴 때 무엇을 어떻게 올릴지 정하는 규칙이다. agb가 받는 문서의 형식, 메타데이터, 상태, 참조 표기, 오류 코드, `.agb.json` 스키마, 형식에 맞지 않는 문서를 올리는 법은 CLI help가 정한다.

- `agb help doc-format`: 형식, 메타데이터, 상태, 참조 표기, 오류와 대처, 맞지 않는 문서 올리기
- `agb help repo-config`: `.agb.json`의 키, 규칙, 예시
- `agb help migrate-v0.8`: v0.8에서 옮겨 오는 절차

올리는 쪽의 폴더 이름이나 문서 규칙은 agb가 알지 못하므로, 맞지 않는 문서는 올리는 쪽이 help대로 맞춘다.

- 서버의 기록 문서는 원문을 고치거나 지울 수 없다. 같은 이름에 다른 원문을 올리면 거절한다. 덮어쓰려 하지 않는다.
- 프로젝트 키(`<KEY>`)는 저장소의 `.agb.json`에 있는 `project`다. `.agb.json`이 없는 저장소는 문서를 자동으로 올리지 않는다. 수동으로 올릴 때는 `-p <KEY>`를 준다.

## 올릴 문서 정하기

- 로그, 코드, 데이터 파일은 올리지 않는다. 그런 파일은 원래 저장소에 두고, 문서에서 경로로 가리킨다.
- 고칠 수 있는 임시 문서(draft) 자리는 없다. 임시 문서는 올리는 쪽 저장소에서만 관리하고, 다듬어지고 결정된 내용만 올린다. 나중에 대체되더라도 그때 올린다.
- 새로 쓰는 기록은 일반 문서로 쓴다. 가져온 문서(`--imported`)는 이름 형식이나 프런트매터가 맞지 않아 일반 문서가 될 수 없는 문서에만 쓴다.
- 전체 대체만 `supersedes`에 쓴다. 일부만 대체하거나 보완하거나 참고하면 `related`에 쓴다.
- 서로 참조하는 문서는 대상을 먼저 올린다. 이름순으로 올리면(시각이 이름 앞에 있다) 이전 기록이 먼저 올라간다.
- 문서의 형식이 agb와 달라도 원문은 고치지 않는다. 원문은 그대로 두고 메타데이터를 인자로 넘겨 맞춘다.
- 올린 뒤에는 아카이브 표시와 관계만 고친다.
- `.agb.json`을 새로 쓰거나 고쳤으면 `agb doc sync`로 서버에 없는 문서가 무엇인지 보고 올린다.
- 대처할 수 없는 거절은 파일명과 사유를 최종 보고에 쓴다.
